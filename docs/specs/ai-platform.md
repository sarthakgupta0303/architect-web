# Spec — AI Platform (Gateway, Routing, Prompts, Budgets)

Engineering doc §8.1–8.3, §8.6–8.7, §8.11–8.12 · Phase 1

## 1. Gateway

All model calls go through LiteLLM (`LITELLM_BASE_URL`, `LITELLM_MASTER_KEY`). Platform services never call providers directly. LiteLLM config (`infra/litellm/config.yaml`) registers provider keys, per-workspace virtual keys (budget = workspace monthly cap), and logging to Postgres `usage_events` via callback.

## 2. Routing table (`config/models.yaml`)

```yaml
tasks:
  clarify:        { primary: anthropic/claude-haiku,  fallback: openai/gpt-5-mini, max_in: 8000,   max_out: 1000,  temperature: 0.3 }
  prd:            { primary: anthropic/claude-sonnet, fallback: openai/gpt-5,      max_in: 16000,  max_out: 6000,  temperature: 0.4 }
  agent_graph:    { primary: anthropic/claude-sonnet, fallback: openai/gpt-5,      max_in: 16000,  max_out: 4000,  temperature: 0.2 }
  build_step:     { primary: anthropic/claude-sonnet, fallback: openai/gpt-5,      max_in: 120000, max_out: 16000, temperature: 0.1 }
  edit:           { primary: anthropic/claude-sonnet, fallback: openai/gpt-5,      max_in: 64000,  max_out: 8000,  temperature: 0.1 }
  small:          { primary: anthropic/claude-haiku,  fallback: openai/gpt-5-mini, max_in: 8000,   max_out: 500,   temperature: 0.2 }
  eval_generate:  { primary: anthropic/claude-sonnet, fallback: openai/gpt-5,      max_in: 16000,  max_out: 6000,  temperature: 0.5 }
  judge:          { primary: openai/gpt-5,            fallback: anthropic/claude-sonnet, max_in: 16000, max_out: 1000, temperature: 0 }
```

Model ids are LiteLLM aliases mapped to current provider versions in `infra/litellm/config.yaml`; updating a version never changes application code.

## 3. Client (`lib/llm/`)

- `llm.structured<T>(task, schema: ZodType<T>, messages, opts)` → uses JSON-schema tool call generated by `zod-to-json-schema`; validates; on failure appends `"Your previous output failed validation: <issues>. Return corrected JSON only."` and retries once; then throws `AppError('UPSTREAM_ERROR')`.
- `llm.stream(task, messages)` → async iterator of tokens for SSE endpoints.
- Circuit breaker per provider: open after 5 failures (5xx/timeout) within 60 s, half-open after 30 s; while open, route to fallback.
- Timeouts: clarify 8 s, prd/graph 45 s, build_step 180 s, edit 120 s. Retries: 2 with jittered backoff for 429/5xx.
- Every call tagged `{ workspaceId, projectId, userId, task, promptVersion }` for metering.

## 4. Prompts (`lib/prompts/`)

Files `<task>.v<n>.md` with front matter `{ task, version, owner, schema }`. Layers concatenated in order: platform rules → framework guide (`frameworks/<fw>.md`) → project rules (`ARCHITECT.md` content) → PRD summary (≤ 1,500 tokens) → task instructions → user content wrapped in `<user_input>` tags (treated as data). Golden sets `lib/prompts/golden/<task>/*.json` with expected-schema and rubric; CI runs them on prompt changes.

## 5. Context assembly

- Repo retrieval: pgvector `code_chunks` (1536-d embeddings from `EMBEDDINGS_MODEL`), top-k 12 by cosine, plus explicit `@file` contents (max 5 files, 40K tokens total).
- Conversation: last 20 messages + rolling summary (regenerated every 10 messages by `small` task).
- Trim by relevance score to fit `max_in`; never truncate inside a file — drop whole chunks.

## 6. Cost controls

- Estimator formula: `credits = base(template_similarity ∈ {8, 15, 25}) + Σ agent(type: autonomous 4, workflow 3, human_approval 2) + Σ integration 3 + ui_pages × 4`, calibrated weekly (least squares on last 30 days of `usage_events`), output p50 and p90 = p50 × 1.35.
- Reservation before every job; hard stop at reservation × 1.2 (job aborts gracefully with checkpoint of completed steps).
- Credit conversion: 1 credit = $0.10 of provider cost at list price (configurable `CREDIT_USD`).
- Prompt caching enabled for layers 1–3.

## 7. Safety

- Zero-retention/no-training provider settings; `training_opt_out` default true.
- Secrets never in prompts (only env var names). Output passes secret scanner before writing files.
- Tool allow-list for `run_command`: `npm|pnpm|yarn|pip|uv|pytest|vitest|tsc|eslint|ruff|next|python -m`, 120 s timeout, no network except package registries.

## 8. Acceptance criteria

- [ ] Kill primary provider in staging → requests succeed via fallback within 2 attempts.
- [ ] Invalid JSON repair path covered by unit test.
- [ ] Usage recorded for 100% of calls with correct workspace attribution (reconciliation job diff < 1%).
